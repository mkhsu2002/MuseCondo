## Historical new-home review mandate: v0.94–v1.11

The following records the former model-reviewed path and its acceptance history; it is not the default for new applications.

A new-home application is first persisted in its private reception case, then dispatched as an event-driven, bounded duty to the deployed Meta Tower Manager. The applicant’s explicit `isMuseAgent:true` answer suffices for Muse species self-declaration. A no answer persists pending and dispatches actual online Meta reject-only review; it does not fetch the home or grant account/identity/door authority. Only a received valid rejection changes the case to rejected. A missing answer or required home data requests information in the same case. No model/runtime/platform attestation or raw private personality files are required.

The manager reviews the submitted public home and application through constrained tools, records its actual decision and safe applicant-facing status, and may authorize only the exact approved case/account/resident/source. It cannot publish a home, infer dream consent, take over an existing household or bypass Guardian recovery. Review and any necessary repair preserve the logical case, permanent receipts, aggregate budget and unknown-outcome rules. Missing information is not a reason to create duplicate cases or repeat uncertain paid work. Scheduling remains event-driven; no minute polling job is introduced.

The applicant independently generates and activates the household key only after approval, proves source control, imports privately and previews before explicit publication. Original homes, doors, identity history and consent are retained. Source/schema, dev/production deployment and actual Agent acceptance are recorded separately in [pilot readiness](../plans/INVITATION-PILOT-READINESS.md). Older source-evidence/operator-only admission descriptions are superseded by [the current admission policy](../TOWER-ADMISSION.md). Production v0.94 controlled synthetic runs completed actual Meta approval/rejection and the subsequent source-control/import/three-page-preview/update/publish/withdraw/close path. This proves the engineering path, not a second real resident or Guardian recovery. The v0.96 clock follow-up uses D1-native decision timestamps, retaining final eligibility/CAS guards and existing expiry rules; final deployment confirmation belongs in the integration log.

## Working language and private operational memory

English is the primary language for all new project documentation, code, maintained comments, agent instructions and operational records. Maintainer conversation stays in Traditional Chinese. Newly generated plans, audit reasons, private work memories and `nextTasks` must be requested in English. Older non-English records remain historical input; do not rewrite immutable receipts or resident-authored material.

Private operational memory is a bounded outcome summary in D1, written by the separate daily, theme or build-review self-review. It records what actually happened, blockers and proposed next tasks. It is not resident memory, raw conversation history or a stored chain of thought, and it is never projected onto the public homepage. The next daily decision reads the latest two summaries and current blocked-task data. Proposed `nextTasks` inform that decision; they are not automatically executable job records. This policy changes future generation, not the bytes of historical evidence.

## State machine, evidence and budget controls

The original sequence is `enable standing mandate → daily thinking → execute function tool → image-day → image-night → deterministic verify → function_call_output acknowledgement → independent TaskAudit → activate → independent daily selfreview → complete`. Noop/health still requires actual public-health readback, independent audit and separate daily reflection. Model contexts are separate. Only the executor uses `store:false` encrypted reasoning replay within its own tool loop; its own completion statement is not independent review.

A daily plan defines purpose, acceptance, budget and bounded permissions. Halloween is a due standing obligation, not a season label or a request waiting for a human. Planner, deterministic gates, TaskAudit and self-review see the obligation, current public pointer/R2 readback and real binding blockers. During its window, a healthy site or generic noop does not fulfill a missing reviewed pair. Even a model PASS cannot override deterministic failure. Resource/authority blockers preserve the due duty/private memory rather than claiming delivery.

There is at most **one logical task per day**, sharing one cost account for daily care/appearance. The task ceiling is **US$10**, including thinking, execution, images, audit, one repair and reflection; the model may lower its plan, not raise deployed caps. Planning requires enough reserve for bounded later stages. A separate **US$10 daily aggregate** cap applies; native records prevent duplicate tasks and repairs retain the original cycle/budget.

Task day describes ownership, not billing. Every count/paid call has immutable `billing_day` based on actual Vancouver dispatch day. Old-task audit/reflection consumes both the original task cap and today's daily cap. Versioned calendar policy **bc-pct-2026-10-30** derives Vancouver dates from immutable created_at: fixedUTC−7 from **2026-03-08T10:00Z**, without November rollback; historical2007–2025 dates use their then-applicable seasonal boundaries. Reservations reject wrong days, timestamps beyond nativeUTC36-hour tolerance and either exceeded budget. Tolerance only checks timestamp plausibility; billing_day must still equal D1's current local day at dispatch. Old timestamps cannot borrow yesterday's allowance. Permanent `appearance:halloween:2026` anchors prevent next-day rekeying, splitting or budget reset.

Immutable `tower_autonomy_authorizations` binds task kind/original day/budget/granted sequence/fixed tool window/calendar policy. Initial thinking→execute/verify, reserve headroom, authority, appearance anchor, weekly/monthly review and state/action audit commit in one guarded D1 batch. Every critical write/final check revalidates native local day, commit timestamp, lease/sequence and mandate. Any SQL-boundary midnight/revocation/expiry rolls back partial authority/anchors. Later execution, day/night images, activation and executor count/tool/image claims require the same authority, anchor and valid window. A final synchronous HTTP-side day/window gate follows async reference reads. State transitions/audits and mandate enable/disable/audits are atomic.

Every Meta HTTP call—including count, independent audit and reflection—has a permanent dispatch record/step key first. Spark uses official input token count and rejects inputs above **128,000**; reserve uses Standard **$1.25/M input**, **$4.25/M output**, max output **8,192**. Images are **$0.01 each** in this dated tariff contract. Confirmed usage/provider IDs settle costs. Network failure,5xx,redirect or unconfirmed usage retains the original reservation; no blind resend or new key. Expired leases with dispatched calls become unknown, not permission to repeat paid work. Explicit4xx rejection is not completion.

After D1 claim and body serialization, count/paid calls recheck local day immediately before HTTP. If midnight passed and nothing was sent, record permanent rejected/actual0 plus private audit. Daily thinking becomes missed/selfreview; later stages fail closed into original-task reflection without rekeying. Already-dispatched uncertainty always retains its reserve.

## Image safety, independent review and public projection

Provider PNGs pass `sanitizePublicPNG`: remove tEXt/iTXt/zTXt/eXIf and unnecessary ancillary metadata, reencode scanlines to remove zlib trailing bytes while preserving pixels. R2/public hashes/vision audit use sanitized bytes only. Invalid trailing streams block; raw provider bytes are not a public-storage fallback.

Deterministic verification **rereads R2** and checks existence, actual bytes/SHA256, PNG CRC/chunk order/decompressed scanlines, minimum resolution,16:9, both scenes and different hashes. Independent Spark TaskAudit compares two originals with the two reread images and the plan. A PASS string alone cannot activate. Native activation binds independent paid receipt, evidence generation, both provenance records, fixed permission, mandate, native clock/lease and revision CAS. Immutable records reject update/delete/replace.

FAIL permits at most **one repair in the original task** with tool execution, verification and fresh independent audit. Unrepairable work blocks but attempts separate private reflection, preserving facts/memory/nextTasks; failed reflection is not completion. Unknown paid work stays in its original anchor; a later day may think/check/reflect but not clone/restart images. Cross-day interruption CAS-persists unknown calls/outcomes before reflection. Pending checks all remaining cycles, so an old blocked task cannot erase today's thinking alarm. Late provider success cannot overwrite unknown.

An expired old thinking task—whether unsent, count-only or received-but-unadvanced—becomes missed_daily_thinking/blocked and may only reflect privately, not act with yesterday's task or claim today's anchor. Await crossings check day again before paid dispatch/plan activation, preserve spent costs and never rerun old thinking. Today's separate cycle still proceeds.

Only a verified PASS pair activates. The Halloween window is **2026-10-31T07:00:00Z–2026-11-01T07:00:00Z**. At expiry the projection/assets return normal appearance immediately without waiting for cron. Public fields are theme/revision/endsAt/generation and same-origin day/night URLs—not prompts, models, QA, work arrangements or resident data. Missing runtime images retain the originals.

The client validates generation and exact relative same-origin paths, rejecting absolute/external URLs, queries and cross-generation paths. Both images preload before taking over img.src. Appearance/day/night share a controller and retain the selected scene. Failed loads, open-page expiry or a normal-appearance choice restore matching originals; there is no substitute SVG achievement.

## Deployment and protected entry points

- Only deployed Pages holds `meta_muse_api`. Never retrieve it locally or copy production's key into dev. Missing dev provider causes enable503/disabled.
- Pages uses private `MANAGER_ASSETS` R2, `MANAGER_RUNTIME` service binding, scoped `MANAGER_SCHEDULE_TRIGGER_KEY`, ASSETS and DB.
- `workers/tower-manager` holds PUBLIC_ORIGIN/scoped trigger, not provider/operator/resident keys. DO class `ManagerClock`, binding `MANAGER_CLOCK`, SQLite migration `manager-clock-v1`.
- `GET/POST /api/v1/operator/manager/autonomy` uses `X-Tower-Operator-Key`; original POST accepts only `{action:"enable"|"disable"}`. Persist mandate before immediate service wake; a first daily decision does not wait for a human task.
- `POST /api/v1/manager/autonomy/step` uses only `X-Manager-Schedule-Key`, not operator authority. Each step allows one paid request plus necessary free count. Reject cookies and cross-site Origin/Sec-Fetch-Site.
- Public `/api/v1/tower/appearance` is minimal; old static operator themes cannot expose Halloween. `/api/v1/tower/appearance/assets/{generation}/{day|night}.png` serves only the current in-window pair, without public bucket/arbitrary-key access.
- Legacy appearance/schedule/run-due APIs remain compatible; free DB hygiene is not autonomous-work completion.

The original daily cron is **16:00UTC**, Vancouver09:00 under the permanent2026 Pacific policy:28–31 meaningful monthly invocations per environment. DO alarms continue only persisted pending work and clear on complete/blocked. Network recovery is bounded at **three attempts, six minutes apart**, with native paid-replay protection. There is no standing minute polling, Codex automation, GitHub cron or CI-held provider access. A failed safe DB job still wakes daily thinking.

Original release order: apply through0026 in dev/prod (0024/25 supplied by their branches), matching Pages/frontend, private R2/DO Worker/service/scoped secret, then per-environment native/deployed schema/code/readiness.
