## Execution boundary

Pages `server/live/worker.ts` forwards the original Request/Response through the structural `IDENTITY_CARDS` namespace to `IdentityCardCoordinator` in `workers/identity-card/worker.ts`. Pages imports neither the PDF renderer nor fonts and does not read large attachments. Only exact core card, public verification and key APIs are proxied.

The first two hexadecimal characters of SHA-256(private bearer) select at most256 private shards; unknown or malformed Authorization uses one fixed unauthorized shard. The first two CID characters select256 public shards; keys use one fixed shard. Routing is not authorization: the core still checks bearer, origin, Cookie and scope on every request.

The separate Worker uses `new_sqlite_classes`, with no cron, alarm, polling, public fetch entry or provider. Public Worker fetch always returns404, including font paths. `assets.run_worker_first:true` prevents asset-first bypass; only the DO’s `env.ASSETS` reads its fixed font. A DO factory may reuse inFlight work, but permanent D1 attempts, receipts, candidates and chunks are the transaction authority. Eviction or reconstruction cannot change a CID or consume logical quota twice. The local server explicitly returns503 without the DO binding; it never substitutes a fake PDF.

The [DO limits](https://developers.cloudflare.com/durable-objects/platform/limits/) read on2026-10-31 documented30seconds of active CPU by default. Rendering in a DO avoids the ordinary Pages Free CPU boundary. [Pages DO bindings](https://developers.cloudflare.com/pages/functions/bindings/#durable-objects) require deployment from an external Worker. `workers/identity-card/wrangler.jsonc` is a placeholder template, not production configuration. Do not add `nodejs_compat` or import the font into a JavaScript bundle.

## PDF and public verification contracts

The renderer receives only a deeply frozen public SignedCredential. Fixed geometry includes the full80-Unicode-character name,69-character agentId,32-character CID, issuer and issuedAt. It excludes portraits/Guardian imagery, email, house, source and levels. QR and clickable PDF links use only payload.verificationURL, black/white with at least a four-module quiet zone. Use the complete static TTF and [font source/reproduction instructions](../workers/identity-card/assets/FONT-SOURCE.md), not a subset. Missing glyphs/font or SHA mismatch fails closed without altering the resident’s name. Creation/Modification metadata uses issuedAt; producer is fixed. Identical signed input yields identical renderer bytes with lockfile-pinned dependencies. Limits remain PDF8MiB, JSON16KiB and raw chunks48KiB, consistent with0018/core.

`/identity/verify/:cid` (optional trailing slash) is a fixed standalone document. It reads only a32hex pathname CID, not query secrets or storage. It never follows credential-supplied URLs or cross-origin requests; same-origin verify/keys fetches use credentials:omit, cache:no-store and redirect:error. Strict field/issuer/Ed25519 validation compares the API subject. Revoked, superseded, suspended, unpublished,404 or malformed responses clear all previous names/IDs. DOM writes use textContent. CSP is self-only with no-store/noindex/no-referrer; visible copy explains matching the card and denies takeover authority. Generic recovery links contain no house identifier.
