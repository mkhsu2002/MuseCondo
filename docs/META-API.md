# Meta API 接通前檢查

目前狀態：**未接通**。本次只檢查 MuseCondo 是否存在 `.env*` 設定檔，以及任務環境是否有 Meta 設定名稱（不輸出值）；未發現可安全重用的設定。沒有讀取或修改全域 Codex 設定，沒有沿用聊天中曾出現的 key，也沒有新增或搬移持久憑證。

已核對官方文件中的端點、圖片模型名稱與協議（如下），但本專案尚未實際呼叫、驗證帳戶能力、取得預算或接通 adapter。前端只有公開建置變數 `MUSE_BASE_PATH`；不得將 key 放在 `VITE_*`、src、public、瀏覽器儲存或資產來源紀錄。

## 官方文件核對（2026-10-28；非 API 實測）

| 項目 | 官方文件記載 |
| --- | --- |
| Base URL | `https://api.meta.ai/v1` |
| 生圖模型 | `muse-image-1.0` |
| 單次生成／編輯 | `POST /v1/images/generations`、`POST /v1/images/edits` |
| 對話式生成／編輯 | Responses API，`POST /v1/responses` |
| 認證 | 服務端 Bearer token；文件中的環境變數名稱為 `MODEL_API_KEY`，此處沒有建立或讀取其值 |
| `size` | 設定寬高比，不保證回傳圖像的精確像素尺寸 |
| Responses `store` | 預設 `true`；可設 `false` 自行管理狀態 |

來源：[Meta Model API overview](https://dev.meta.ai/docs/overview)、[Image generation guide](https://dev.meta.ai/docs/image-generation)。以上是文件已核對的規格，不代表目前帳戶可用、實際 metadata 已回傳、計費已核准或圖片已生成。住戶頁面的模型欄位仍維持「尚無可驗證資料」；素材 manifest 的實際生成欄位仍為 null。

### 個性資料與狀態保存

尚待實作的 Responses adapter 對涉及授權個性資料的請求，應明確評估並設定 `store: false`，不能依賴預設值。保留必要的匿名化個性摘要與構圖描述即可，不能把完整私人記憶、主人身分、憑證或與生成無關的歷史一併傳送。分析授權仍須涵蓋送到 Meta API 的資料；`store: false` 不取代授權，也不能被宣稱為全面零留存保證。

若使用無伺服器對話保存模式，依官方格式只重送必要的前次生成項目或已批准的參考素材，並由本方保存最小狀態與來源紀錄；先以受控資料驗證是否能維持同一住所雙構圖。`size` 的目標比例為桌機 16:9、手機 9:16，實際回傳尺寸須檢查，不能把要求數值當作輸出尺寸證明。

圖片模型預設可能使用內部網路／圖片搜尋。為限制資料外流與維持參考素材來源，接通設計需評估關閉 `enable_image_search`、`enable_web_search`、`enable_shell`，僅提供已批准且由 Meta API 生成的參考圖。這些設定目前尚未送出任何請求。

接通前由操作者確認：

1. 依上述官方規格驗證實際帳戶能力、認證與端點可用性。
2. 帳戶可使用的文字與生圖模型、實際模型 metadata 來源。
3. 已批准的模型、預計圖片數及費用。未批准前不送付費請求。
4. 既有安全設定是否可直接由服務端讀取；若需新增持久憑證或搬移 key，先取得所需批准。
5. 遠端 idempotency、工作狀態查詢與生成 ID 恢復能力；不確定結果不可盲目重試。
6. 已授權資料的傳輸、公開摘要 allowlist、圖片輸入是否可能包含私人資訊，以及產物來源驗證。

只有完成這些檢查後，才實作 `MetaGateway` 的真實 adapter。所有分析、提示詞、參考圖、住家圖、禮物圖與樓管工作只走此服務。不能為了先補視覺而改走 OpenAI、Fal、其他模型或非 Meta 生成的舊品牌素材。
